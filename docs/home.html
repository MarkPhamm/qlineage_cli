What feeds this SQL model, and how the query gets there.

QLineage parses Snowflake and Redshift SQL on your machine. Open a file and see the CTEs, the joins, and the columns. Point it at a dbt model and it uses the compiled SQL, then shows what that model refs and what refs it.

One column--column revenue
  1. The parser is SQLGlot. CTEs, joins, and the columns each scope reads come from the statement itself.
  2. dbt is optional. When target/manifest.json is nearby, compiled SQL and friendly ref and source names replace the physical tables.
  3. The neighborhood stays on one model: +fct_orders upstream, fct_orders+ downstream, fct_orders+1 for a single hop.

From the statement to each node

-- examples/sql/customer_revenue.sql
with orders as (
    select order_id, customer_id
    from raw.shop.orders
),
payments as (
    select order_id, amount
    from raw.stripe.payments
),
final as (
    select o.customer_id,
           sum(p.amount) as revenue
    from orders o
    join payments p using (order_id)
    group by 1
)
select * from final
# around one model, both directions
qlineage --model fct_customer_revenue

# upstream only, or one hop downstream
qlineage --select '+fct_customer_revenue'
qlineage --select 'fct_customer_revenue+1'
qlineage models/marts/fct_orders.sql
qlineage query.sql --format tree
qlineage query.sql --format mermaid
qlineage query.sql --column revenue

The workspace names each node, lists the columns it produces, and shows the SQL that built it. The terminal prints the same graph as a tree, JSON, or Mermaid.
